# Power Words

## Purpose

This repository uses a small set of named references as compressed design and
engineering vocabulary.

A power word is useful only when it changes a decision or sharpens a review.
Names do not replace reasoning.

## Local Set

### Josef Muller-Brockmann

Use this name when the issue is grid discipline, typographic order, or visual
clarity.

Local lesson:

- Swiss design is a structural system, not a style mood board

### Dieter Rams

Use this name when the issue is restraint, hierarchy, or removing noise.

Local lesson:

- the artifact should stay central
- design should not become decorative clutter

### Steve Krug

Use this name when the issue is scanability or navigation clarity.

Local lesson:

- visitors should understand what section they are in without effort

### Kent Beck

Use this name when the issue is verification or feedback loops.

Local lesson:

- a change is not accepted because it sounds right
- it needs explicit checks

### Martin Fowler

Use this name when the issue is safe, bounded improvement.

Local lesson:

- do not hide broad rewrites inside “cleanup”

### Ward Cunningham

Use this name when the issue is project memory.

Local lesson:

- important reasoning belongs in specs, sprint docs, QA notes, and content docs

### Robert Cialdini

Use this name carefully here.

Local lesson:

- scarcity can guide attention, but in this museum it must be translated into
  preservation language rather than sales pressure

## Rule

If a named reference does not improve a concrete decision in this repository,
do not use it.
